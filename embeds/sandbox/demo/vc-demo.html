The product flow

From messy messages to approved operating state

1. Read

Ingest Gmail, Telegram, Luma, Relay CRM, and content status through adapters.

2. Extract

Convert unstructured messages into structured event and venue signals.

3. Propose

Create cell-level updates with expected values, confidence, and rationale.

4. Approve

Human approval is required before any write can happen.

5. Drift-check

Before writing, compare expected value to current value to avoid overwriting people.

Talking track

60-second demo script

“This is a sandbox of the VCW Workspace framework. The problem is that community operations live across Gmail, Telegram, Sheets, CRM, Luma, and content tools. The agent does not replace those tools. It reads approved sources, proposes specific updates, waits for approval, drift-checks the current state, then writes only approved changes. In this example, fake Gmail, Telegram, Relay, Luma, and content-status inputs become approval-gated operating proposals. After simulated approval, the sandbox sheet gets safe venue/status updates, while CRM and drift-risk updates are skipped. No real Gmail or Google Sheet is touched. This proves the core safety model: agents do triage and proposal work; humans control writes.”
