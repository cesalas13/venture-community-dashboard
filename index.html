Beginner guide
Use this page when you are not sure where to click.
The dashboard is a control room for Venture Community work. It shows what needs attention, where each workflow belongs, what is safe to demo, and what should wait for approval.
What is live
Only the newsletter automation is treated as live, and it is still WIP.
Everything else is a product surface, planning note, or sandbox demo. If something could write to Gmail, Sheets, a newsletter, or an automation account, it should pass through Human in the loop first.

Context paths
Three ways to build stronger product context.
GranolaUse transcripts for Speaker Prep. Pull deeper explanations, rate responses 1 to 10, and build questions from high-quality patterns instead of generic prompts.
TelegramRun an approved trial scrape, then tune the workflow with local LLM output at no API cost before it becomes a real product.
GmailUse the Emerging account or approved personal-account trial to find context and inputs for the Events Sheet flow. OAuth access requires owner approval.
Cost posture
Keep spend low until the workflow proves utility.
Free firstUse rule-based checks, local LLMs, and prompt assembly before paid model calls. Use Haiku only when API output is worth metering.
CeilingMost of the stack can stay free; paid pieces should top out around $40/month unless utility is proven.
RiskLonger drafts and repeated revise rounds raise cost quickly. Cap cadence before live API use.
Free path
Prompt assembly avoids new API spend.
The local LLM can assemble a structured prompt, then the operator pastes it into ChatGPT or Claude. Workflow logic stays intact while generation moves to an already approved interface. Gemini free tier may be viable for tests if usage stays inside one approved account and published limits.
NeedPermissions for Telegram scrape, Gmail OAuth path, and a directional budget.
TakeawaySOP context plus permissions unlock the next phase; sandbox remains local HTML until live product context is approved.

Automation cost procedure map

Use this map before automating a product: decide the product lane, source, cost level, approval point, and final output.

1
Pick the product lane
Event Ops, Venue, Newsletter, Speaker Prep, Sponsors, or Outreach owns the work.
2
Choose the source
Use Gmail, Sheets, Telegram, Luma, Relay, Google Docs, or n8n depending on where the signal starts.
3
Estimate the cost
Prefer free tools and rule-based checks. Use AI only for reading, drafting, ranking, or judgment-heavy work.
4
Finalize safely
Send the result to Human in the loop. Only the newsletter automation is live; every other write stays draft, sandbox, or manual until approved.
Event OpsLow-cost reads from Gmail, Telegram, Luma, and Sheets. Final output is an approved event update.
NewsletterThe only live automation. Medium-cost drafting and link checks. Still WIP while cadence and debugging finish.
VenueResearch and outreach drafts. Final output is a Gmail draft or tracker update after approval.
SponsorsProspecting and fit scoring. Final output is a ranked list, draft, or one-pager for review.
Speaker PrepBio, panel questions, and briefing drafts. Final output is a prep doc ready for human editing.
OutreachRelationship ranking and follow-up drafts. Final output is a reviewed reply or contact-list note.
